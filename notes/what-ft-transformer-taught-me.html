FT-Transformer 教会我的表格建模What FT-Transformer Taught Me About Tabular Data

表格数据没有天然的序列结构。Feature Tokenizer、CLS token 和 5 折验证让我重新理解了让模型学习特征交互这件事。Tabular data has no natural sequence structure. Feature tokenization, CLS tokens and 5-fold validation changed how I think about feature interactions.

Experiment Log 2026 年 8 月 16 日Aug 16, 2026 6 min read AttentionCoo

表格数据没有像文本那样的天然序列结构。每一列都可能有自己的类型、尺度和缺失模式，简单拼接成一个向量通常能工作，但也会让模型很难显式建模特征之间的交互。

FT-Transformer 给我的启发不是 Transformer 更高级，而是：如果换一种表示方式，让每一列变成一个 token，模型就有机会把特征关系当成上下文来学习。

把列变成 token

Feature Tokenizer 为每个特征学习一个嵌入，把数值列和类别列映射到同一个表示空间。再加上一个 CLS token 作为聚合位置，Transformer 就能在特征 token 之间做注意力。

这仍然需要强先验和正则化。模型中加入了特征残差连接和 DropPath，目的不是追求复杂，而是让训练更稳定、更不容易过拟合。

验证流程比模型更值得复用

表格任务里最容易高估自己的环节通常是验证。缺失值填充、特征工程和超参数选择如果看了太多验证集信息，交叉验证分数就会变得乐观。

这次实验采用分层缺失值填充和 5 折交叉验证，并用五折集成推理得到最终提交。最终 5 折 CV 准确率为 84.51% ± 1.24%，比单次切分更能说明模型的稳定性。

我真正学到的三件事

  • 表示先于架构：同样的 Transformer，如果输入表示不适合表格特征，收益会很有限。
  • 正则化是系统性工作：DropPath、残差、缺失值策略和验证切分需要一起考虑。
  • 报告波动范围：只报一个最好分数，无法说明模型是否可靠。

下一步

我想继续比较树模型与深度表格模型的误差结构，并把这套特征工程和验证流程整理成可复用的实验模板。对表格任务来说，真正稀缺的不是模型结构，而是可信的评估方法。

Tabular data has no natural sequence structure like text. Each column has its own type, scale and missingness pattern. Concatenating everything into a vector can work, but it makes feature interactions hard to model explicitly.

The lesson from FT-Transformer was not that Transformers are inherently better. It was that changing the representation so each column becomes a token gives the model a chance to learn feature relationships as context.

Turning columns into tokens

A feature tokenizer learns an embedding for each feature, mapping numeric and categorical columns into a shared representation space. A CLS token provides a pooling position, allowing attention across feature tokens.

This still needs strong priors and regularization. The model uses feature residual connections and DropPath, not to add complexity, but to make training more stable and less prone to overfitting.

The validation pipeline matters more than the model

In tabular tasks, validation is where it is easiest to fool yourself. If imputation, feature engineering or hyperparameter choices peek at validation data, CV scores become optimistic.

This experiment used stratified imputation and 5-fold cross-validation, with five-fold ensemble inference for the final submission. The 5-fold CV accuracy was 84.51% ± 1.24%, a more useful signal than a single split.

Three things I learned

  • Representation comes before architecture: the same Transformer gains little if the input representation is wrong for tabular features.
  • Regularization is systemic: DropPath, residuals, missing-value strategy and validation splits need to be designed together.
  • Report variance: a single best score does not show whether the model is reliable.

Next

I want to compare error structures across tree and deep tabular models, and turn this feature pipeline into a reusable experiment template. For tabular tasks, the scarce resource is not model architecture. It is trustworthy evaluation.
