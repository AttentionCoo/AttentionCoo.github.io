为什么可审计的 Agent 更重要Why Auditable Agents Matter

在高风险场景里，答案只是系统输出的一部分。证据、工具调用、专家意见和回退路径共同决定了系统是否值得信任。In high-stakes settings, the answer is only one part of the system output. Evidence, tool calls, expert opinions and fallback paths determine whether the system deserves trust.

Research Note 2026 年 10 月 18 日Oct 18, 2026 7 min read AttentionCoo

当我们评价一个 AI 系统时，最容易做的一件事是看最终答案是否正确。但在临床决策、研究辅助或任何高风险工作流里，正确率不足以回答一个更重要的问题：当系统给出一个决定时，我们能否知道它是怎么走到那里的？

这就是可审计性。它不是给系统加一个漂亮的日志面板，而是让证据、工具、协作和不确定性成为系统的一等输出。

黑箱并不等于智能

一个模型可以给出看似合理的结论，却引用错误的证据；可以调用正确的工具，却遗漏禁忌症；也可以在多个 Agent 之间形成共识，但共识只是重复同一个错误。

一个值得信任的系统，不是永远不会失败的系统，而是失败时可以被定位、被讨论、被修正的系统。

因此，可审计性至少意味着：使用者能够检查输入和输出之间的关系，理解关键动作发生在哪里，并对系统的结论保留有意义的异议空间。

三个可审计层次

  • 证据层：每个关键结论都应该能追溯到具体来源，而不是只留下模糊依据。
  • 决策层：工具为什么被调用、在什么时候调用、调用失败后如何回退，应该和最终答案一样可见。
  • 运行层：系统是否真的完成了它声称的流程？SSE 流、结构化状态和测试都能帮助回答这个问题。

在卒中 CDSS 里如何体现

在 stroke-multi-agent-cdss 中，我们把过程拆成几个可检查的节点：Hybrid RAG 负责证据检索，三位专家 Agent 进行交叉质询，18 个领域工具按临床优先级调度，最后通过证据仲裁形成共识。

全链路 SSE 让使用者看到推理和工具执行的过程，而不只是等待一个最终回答。重点不是让用户读大量日志，而是让他们在需要时能够回到关键节点。

代价与边界

可审计性有成本：更多的中间状态意味着更高的延迟、更复杂的界面，以及更难设计的评测。一个系统也不必把所有内部细节都暴露给所有人。

更现实的目标是分层透明：默认给出简洁结论，同时让专家可以下钻到证据和工具轨迹；让系统的不确定性显式存在，而不是被语言流畅度掩盖。

结语

Agent 的价值不只是自动化，而是把复杂工作流组织成可协作、可检查的形式。越接近真实世界的决策，越需要把可信从形容词变成一个可以被验证的工程属性。

When evaluating an AI system, the easiest thing to measure is whether the final answer is correct. In clinical decisions, research assistance or any high-stakes workflow, accuracy cannot answer a more important question: when the system makes a decision, can we tell how it got there?

That is auditability. It is not a decorative log panel. It means making evidence, tools, collaboration and uncertainty first-class outputs of the system.

A black box is not intelligence

A model can produce a plausible conclusion with the wrong evidence. It can call the right tool but miss a contraindication. Multiple agents can agree while repeating the same error.

A trustworthy system is not one that never fails. It is one whose failures can be located, discussed and corrected.

At minimum, auditability means users can inspect the relationship between inputs and outputs, understand where key actions happened, and retain meaningful room to disagree with the result.

Three layers of auditability

  • Evidence layer: every important claim should trace back to a concrete source.
  • Decision layer: why a tool was called, when it was called and how failures were recovered should be as visible as the final answer.
  • Runtime layer: did the system actually perform the process it claims? SSE streams, structured state and tests help answer that question.

What this looks like in the stroke CDSS

In stroke-multi-agent-cdss, the process is split into inspectable stages: Hybrid RAG retrieves evidence, three specialist agents cross-examine each other, 18 domain tools are scheduled by clinical priority, and evidence arbitration produces a consensus.

Full-chain SSE exposes reasoning and tool execution instead of asking users to wait for a final answer. The goal is not to make everyone read a wall of logs; it is to let experts return to critical moments when needed.

Cost and boundaries

Auditability has a cost: more intermediate state means more latency, more interface complexity and harder evaluation. A system does not need to expose every internal detail to everyone.

A more realistic goal is layered transparency: concise conclusions by default, with the ability for experts to drill into evidence and tool traces. Uncertainty should be explicit rather than hidden behind fluent language.

Closing

The value of agents is not only automation. It is the ability to organize complex workflows into collaborative, inspectable forms. The closer a system gets to real-world decisions, the more trust has to become a verifiable engineering property.
